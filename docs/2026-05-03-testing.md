# Test-Strategie (Stand 2026-05-03)

## Grundsatz

> Tests sollen Bugs finden, nicht Code-Coverage-Zahlen pumpen.

Jeder Test in diesem Projekt muss eine konkrete Frage beantworten:
„Was ginge schief, wenn dieser Test fehlt?". Wenn die Antwort nichts
Sinnvolles ist, gehört der Test gelöscht.

## Drei Ebenen

### 1. Unit-Tests (`test/unit/`)

**Wann?** Für jede pure Dart-Logik, bei der ein Bug echte Konsequenzen hat.

Kandidaten in diesem Projekt:
- `CurrencyFormatter` – Geld-Konvertierung (Schritt 1, ✅ vorhanden).
- `PasswordHasher` – Argon2id-Wrapper (Schritt 3).
- `ReceiptParser` – OCR-Text → Positionen + Gesamtbetrag (Schritt 6).
- `BudgetCalculator` – Restbudget, Aggregationen über Kategorien (Schritt 4).
- `StatisticsAggregator` – Daten für Charts (Schritt 8).

Eigenschaften:
- Schnell (< 100 ms pro Test).
- Keine Flutter-Bindings, kein I/O.
- Mit `mocktail` werden externe Abhängigkeiten gemockt.

### 2. Widget-Tests (`test/widget/`)

**Wann?** Für Widgets, die nicht-triviale Logik enthalten oder an
Provider/State gekoppelt sind.

Kandidaten:
- Login-Form (Schritt 3) – Validierung, Fehleranzeige, Cooldown-Hinweis.
- Ausgabe-Formular (Schritt 5) – Pflichtfelder, Betragsformat.
- Kategorie-Auswahl (Schritt 4).
- Budget-Ring auf dem Dashboard (Schritt 7) – Farbwechsel bei
  Schwellwerten.

**Nicht testen** mit Widget-Tests: rein dekorative Layouts, statische
Texte, Icons. Das ist nur Wartungsaufwand ohne Erkenntnisgewinn.

### 3. Integration-/E2E-Tests (`integration_test/`)

**Wann?** Für die wichtigsten User-Journeys von Anfang bis Ende.

Geplante E2E-Szenarien (jeweils einer pro Feature, kein „Alles testen"):

1. **Smoke (Schritt 1, ✅):** App startet → Splash → Login → Home.
2. **Erstregistrierung (Schritt 3):** Account anlegen → einloggen → ausloggen → wieder einloggen.
3. **Manuelle Ausgabe (Schritt 5):** Ausgabe anlegen → in Liste sichtbar → Restbudget verringert.
4. **Bon scannen (Schritt 6):** Test-Bild → erkannte Positionen → in Kategorie speichern.
5. **Statistik (Schritt 8):** Mehrere Test-Ausgaben → Diagramme zeigen erwartete Werte.
6. **Auto-Logout (Schritt 3 + 9):** App im Hintergrund → nach N Min wieder öffnen → Login-Screen.

## Was wir nicht testen

- Theme-Detail-Pixel (Brüchig, kein Mehrwert.)
- Reine Konstanten-Dateien ohne Logik.
- Triviale Getter/Setter.
- Externe Bibliotheken (deren Tests sind deren Verantwortung).

## Coverage-Ziel

Kein hartes Prozent-Ziel. Stattdessen: **alle in Schritt-Modulen
benannten Kandidaten oben sind bei Feature-Abschluss getestet.**
Vor Release (Schritt 9) wird `flutter test --coverage` ausgeführt
und das Ergebnis manuell reviewt – nicht automatisch durchgewunken.
